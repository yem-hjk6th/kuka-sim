# Hilbert corner test (simulation only)

Generated by `python scripts/run_hilbert_corner.py`. Nothing here was run on the robot; the KRL file carries the NOT RUN header. Every speed below is a **model estimate** unless it is a commanded value.

**Scope of the checks:** checked against cell.yaml only; site keep-outs must be checked locally before running. The obstacles are the clamp estimates and the optional `keep_out` list in `config/cell.yaml` (empty in the repository).

## Layout

- Hilbert curve order 3: 64 vertices, grid step 42.86 mm, side 300 mm, centre (685.5, -396.4) mm in BASE 0.
- Side and centre: fitted: largest square (rounded down to 10 mm) whose points are all reachable and collision-free with the vertical nozzle, at least 20 mm from any infeasible point and the bed edge and at least 60 mm (XY) from the inflated clamp boxes (map grid 5 mm), capped at 300 mm. The unreachable +X/-Y bed corner and the clamp boxes are outside it.
- Layer Z: z(x, y) = z0 + kx (x - x0) + ky (y - y0) with z0 = 2.25 mm (bed top_z 0.95 + layer height 1.3), kx = 0, ky = 0, (x0, y0) = (685.5, -396.4); Z 2.25 .. 2.25 mm over the path. Nozzle vertical, rotation 0 deg about it (A0 B90 C0 for 0), TOOL 3.
- Path length 2700 mm, 50 corners (24 left, 26 right turns); model print time 226 s.

## Corner speed schedule

- Mode `krl` (default): set in the program itself, path-synchronous. Straight: $VEL.CP = 12 mm/s. Every corner leg is split at +-6 mm around the vertex (d_zone >= 2 x C_DIS = 6 mm) and the two corner sub-segments run at $VEL.CP = r x v, back to v after them. Speeds assume $OV_PRO 100 %; the ratios hold at any constant override. Extruder rpm fixed. `schedule.csv` lists the zones for reading the logs.
- Mode `pc` (option, `speed_mode: pc`): one $VEL.CP and a PC-side controller switching $OV_PRO per `schedule.csv`. That needs a PC-side schedule follower, which this repository does not provide.
- Ratios 0.5, 0.7, 0.85, 1, 1.15, 1.3, 1.5, each at least 2x, seeded random order (seed 1).
- Minimum straight between corner zones: 15 mm. **Assumption:** the extruder flow responds within a few tenths of a second; at about 12 mm/s 0.3 s is about 4 mm, so 15 mm (about 4 response times) keeps one corner's transient out of the next. Shorter -> r = 1.
- Straight lengths between corner zones: 30.9 .. 116.6 mm; vertex-to-vertex segments 42.9 .. 128.6 mm.
- Corners set to r = 1 because a neighbour is too close: none.

## Corner-speed model (estimate)

Assumptions: the C_DIS blend is the quadratic Bezier through the vertex as control point, of half-length d = min(C_DIS 3 mm, half the shorter adjacent segment); speed follows the commanded speed with a trapezoid profile at 500 mm/s^2 (assumed), is capped by sqrt(a_lat R) with a_lat 500 mm/s^2 (assumed); the corner $VEL.CP applies from the zone start (no PC latency); inside each blend the commanded speed is scaled by the corner dip factor 1 (1.0 = no dip). None of these numbers was read from the controller.

- Blend half-length 3 mm, min radius 2.12 mm; cap sqrt(a_lat R) = 32.6 mm/s.
- Predicted corner/straight ratio: 0.500 .. 1.500; max deviation from the commanded (quantised) ratio 0.000. Per corner: `waypoints.csv` (`model_ratio`), speed profile: `speed_profile.csv`, `speed.png`.
- With the dip factor at 1.0 nothing limits the corner speed at the default settings, so the model simply returns the commanded ratio. Real controllers do slow down below the programmed speed in blended 90 deg corners; the model does not know by how much (`corner_dip_factor` is a placeholder), nor the KRC's own ramps or look-ahead.
- **The logged speed decides.** The corner speed and ratio actually reached come from the controller log ($VEL_ACT or a trace), not from this model.
- Predicted corner bead width relative to the straight bead (**model only**: flow / speed at fixed rpm, no flow dynamics, no corner dip unless set) = 1 / model ratio: 0.67 .. 2.00 (`model_only_width_rel` in `waypoints.csv`).
- Sensitivity to C_DIS (model): highest corner ratio before the blend radius caps the speed: C_DIS 0.5 mm -> 1.11, C_DIS 1 mm -> 1.57, C_DIS 2 mm -> 2.22, C_DIS 3 mm -> 2.71, C_DIS 5 mm -> 3.50.

## What the lab still has to measure

- The real TCP speed through each corner ($VEL_ACT or the trace at the controller's IPO rate) against `model_ratio`; the real ramp / blend behaviour replaces the assumed accelerations.
- The extruder flow response time behind the 15 mm minimum straight.
- Corner bead width per corner id (and straight bead width next to it) to get width vs r.
- TOOL 3 re-confirmation, the bed top over the square (top_z varies 0.95 .. 1.38 mm) and the clamp positions (photo estimates) before any run.
- Site keep-outs (hopper, hose, cables, cage, anything not in cell.yaml): added to a local copy of `config/cell.yaml` (`keep_out`) and checked locally before running; never committed.
- The controller's INI / BAS(#INITMOV,0) defaults the program relies on ($ACC.CP, $VEL.ORI, ...).
